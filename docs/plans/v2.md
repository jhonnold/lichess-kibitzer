# Plan — lichess-kibitzer v2 (stacked PRs)

## Context

Implement `~/documents/lichess-kibitzer/v2/PRD.md` (terms: `GLOSSARY.md` beside it). v1 on `main` (`25a9269`) = one picked game, one engine on `go infinite`. v2 = Admin registers Event once; top-N Boards tracked per Round; one engine works a two-tier Queue of `go movetime T` Jobs; MultiPV lines stored per ply; Cursor navigation + labelled arrows; status/metrics; overview; Archive. Ship as one `gh stack` of 21 PRs in PRD vertical order, backend → viewer inside each. Site is internal-only, so PRs need not be deploy-safe, but each is green.

## Findings that shape the plan

- Round PGN stream already carries all Boards; `parseGame(text, gameId)` filters by `GameURL` tag (`src/lichess/stream.ts`). Board order only from `fetchRound` `games[]` order (`src/lichess/api.ts`).
- `Engine.search` already serialises `go movetime` and `stop()` resolves the stopped search (pre-emption works as is). `SearchResult.info` keeps only multipv 1 → must keep all lines. Position is `startpos moves …` only (fine).
- `fake-uci.mjs` ignores `position`; needs a crash-on-position flag for restart/DLQ tests.
- chessground 9.2.1 `DrawShape` has `label: {text, fill}`, `modifiers.lineWidth`, custom brushes with opacity; `setAutoShapes` survives `fen` sets. PRD open question closed (read from npm cache tarball, not node_modules).
- `EvalGraph` has `events: []` (no clicks); `MoveList` no clicks; `Viewer` has no key handlers; `positionOf` replays all plies only; `Ply` has no arrival timestamp (ticking clocks need one).
- `node_modules` absent → `npm ci` in each worktree. No `prom-client` yet.
- Reuse: `moveMark`/`winPercent` (`shared/accuracy.ts`), `play`/`legalDests`/`evalSeries` (`shared/viewer.ts`), `toScore`/`pvToSan` (`src/kibitzer.ts`), `fileStore` atomic write (`src/store.ts`), HMAC cookie auth (`src/routes/admin.ts`), SSE throttle (`src/routes/events.ts`), `ReplaySource`, `helpers/sse.ts`.

## Design decisions (mine; not in PRD)

- **Additive then switch.** PRs 1–5 add v2 modules beside v1 (v1 stays green); PR 6 rewires server/routes/reducer/viewer and deletes v1 `kibitzer.ts`/`state.ts`. PR 6 will exceed the ~500 LOC guide.
- **Types** (`shared/types.ts`): `Eval {score, depth, kind: 'complete'|'provisional', bestmove, lines: PvLine[]}`; `Ply` gains `at` (ms, arrival) for clocks; `BoardGame` (game + `board` number + `tracked`); `RoundState {tourId, roundId, name, startsAt, boards[]}`; `JobStatus` per board (`queued` + position, `searching` + depth, `done`); `SseEvent` variants carry `boardId`.
- **Storage:** `data/state.json` (`version: 2`: event, engine config, job time, N, current round id, DLQ) + `data/rounds/<tourId>/<roundId>.json` per Round. Archive = those files once the Round is no longer current, so nothing is lost before the Archive PRs. v1 file → discarded on boot.
- **Queue** is a pure module (`shared/queue.ts`): enqueue/supersede/next/pre-empt decisions and crash counts; the scheduler owns the engine and timers. Not persisted; rebuilt from plies lacking a Complete eval.
- **Job time:** no default in code until PR 8 measures it; before that, tests inject it and the Admin must set it (Queue idle while unset).
- **Opening name:** server-side, as node-tlcv does (`~/projects/node-tlcv/src/services/lichess.ts` `fetchOpening`): `GET https://explorer.lichess.org/masters?play=<uci,…>` → `eco name`. Looked up per Board while the game is in book (stop after the first null or failure for that Board), through the existing `api.ts` request queue so 429 handling applies; stored on the Board and archived.
- **Berserk for PR 8:** build from `~/projects/berserk` in a separate worktree at latest `main` (never touch the working copy); binary kept outside the repo.

## Orchestration

Per layer n, worktree `~/projects/lichess-kibitzer-wt/v2-<n>` on a branch cut from layer n−1 (`npm ci` once, reuse via copy-free fresh installs):
1. planner (`general-purpose`, opus) → `scratchpad/v2-<n>-plan.md` (per memory; not `Plan` type).
2. plan-reviewer (opus) edits the file in place.
3. implementer (sonnet for 5, 6, 13; haiku otherwise) builds, runs gate, commits (conventional).
4. code-review subagent (opus); fixes loop through the implementer.
Orchestrator never codes; keeps only layer summaries. Later layers get the previous layer's summary + the plan file.

Stack: `gh stack init --base main <branches>` → `gh stack submit --auto --open` → fix titles/bodies via `gh api -X PATCH`. v1 saw no CI after a >3-branch push; workflow now exists on `main`, so verify with `gh pr checks` per PR and close/reopen any PR with no run. User merges.
